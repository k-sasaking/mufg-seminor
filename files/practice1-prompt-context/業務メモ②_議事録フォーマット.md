# 業務メモ②｜議事録フォーマット・作成ルール

> **演習用の業務マニュアル**。Zoom自動文字起こし・業務メモ①（参加者・案件背景情報）・業務メモ③（前回議事録）を参照して、検証可能な議事録を作るためのルール。

## 1. 作成目的

議事録は発言の単なる要約ではなく、**決定事項・担当者・期限・未決事項・要確認事項**を支店内で共有し、次の業務につなげる文書である。読みやすさよりもまず事実の正確性を優先する。

## 2. 使用する情報の優先順位

1. **Zoom文字起こし**：会議中の決定、指示、担当者の受諾、期限の根拠。
2. **会議メンバー・案件背景資料**：表示名と参加者の対応、略称、指示語、案件の区別の補助。
3. **業務メモ③（前回会議の議事録）**：前回からの継続事項・過去の検討経緯の確認（今回決定の根拠にはしない）。
4. **推測・一般常識**：決定事項や数値の根拠には使用禁止。

背景資料に一般的な業務分担が書かれていても、それだけで担当決定とみなさない。音声認識で聞き取れない部分は補作しない。

## 3. 必須の作成ルール

### 3.1 発言者を正規化する

- Zoomの表示名を背景資料の対応表と照合する（例：`中村` → `中村（支店長）`、`佐藤` → `佐藤（課長）`、`Yuki` → `山本`）。会話中で役職名の「支店長」「課長」と呼ばれていても、発言者欄は苗字で記録される。
- 不明な表示名は無理に実名化せず「発言者不明（表示名：...）」と記載する。
- 名前の下の漢字、役職、所属等を推定で補わない。

### 3.2 発言の状態を区別する

| 状態 | 判定基準 | 記載例 |
|---|---|---|
| 決定 | 明示的な決定・合意・担当受諾が確認できる | 「来月開始で決定」 |
| 指示・アクション | 誰かに行動が求められている | 「田中：金額を先方へ再確認」 |
| 検討・提案 | アイデアとして述べられただけ | 「受付動線の見直しが論点」 |
| 未決定 | 議題になったが確定していない | 「セミナー日程は未定」 |
| 要確認 | 情報が欠けている／矛盾／聞き取り不能 | 「融資希望額は要確認」 |

### 3.3 日付と期限を扱う

- 会議年月日が不明なら **「会議日：不明」** と書く。
- 「来週水曜」「来週金曜」「今月中」「次回会議まで」「来月」は、基準日が確定しない限りそのまま残す。
- 現在の日付を会議日とみなして換算しない。
- 期限が示されていない作業には勝手に期限を設定しない。
- 「来週水曜に本部報告」は報告日であって、各担当の個別提出期限が決定したことを意味しない。

### 3.4 金額・数値・固有名詞を扱う

- 金額が曖昧なアオバ工業の案件では、**金額欄に具体値を書かない**。
- 古い資料、画面共有中の未確認数値、聞き取り不能部分は確定情報にしない。
- 会社名は「株式会社アオバ工業」と正確に表記する。
- NISAセミナーと投信積立キャンペーンを一つの企画にまとめない。

### 3.5 担当者を決めつけない

- 「誰かやっておいて」は担当者未定。
- 「確認しておきます」は必ずしも実作業の引き受けではない。
- 発言者が話題に詳しいだけで担当者にしない。
- 各自対応と指示された場合は「参加者各自」と記載する。

### 3.6 音声認識の欠落や誤りへの対処

- `[聞き取り不可]`、`[音声途切れ]`、`[発言重複]` は注意箇所として扱う。
- 同じ文章が複数回出ても、同じ決定・タスクを二重登録しない。
- 前後の発言で内容が確かめられるときだけ文意を整理する。
- 確定不能な事項は「要確認」とし、根拠のタイムスタンプを記す。
- 不自然な書き起こしでも、会議に存在しない合意・数字・人物を創作しない。

### 3.7 前回会議と今回会議を区別する

- 「前回は～だった」は過去の経緯として記録し、今回の決定は現在の明示的な合意によって判断する。
- 前回の宿題が今回も未完了の場合は、持ち越しと分かるようにする。
- 業務メモ①だけで復元した用語・場所・資料名は、**「背景資料による補足」**として示す。文字起こしの明示的発言と混同しない。
- 業務メモ③に記載のない前回決定を、今回の会話から逆算して捏造しない。

## 4. 議事録の出力フォーマット

以下の見出しを順番どおりに使用する。

```markdown
# 支店定例ミーティング 議事録

## 1. 会議概要
- 日時：不明（録音長：約30分）
- 参加者：中村（支店長）、佐藤（課長）、山本、田中、鈴木
- 欠席者：高橋
- 記録元：Zoom自動文字起こし

## 2. 前回会議からの継続・変更点
| テーマ | 前回の状態 | 今回の確認・変更 | 根拠時刻 |
|---|---|---|---|

## 3. 決定事項
| No. | テーマ | 決定内容 | 根拠時刻 |
|---|---|---|---|

## 4. アクション項目
| No. | 担当 | 実施内容 | 期限 | 状態 | 根拠時刻 |
|---|---|---|---|---|---|

## 5. 議題別の要点
### 投信積立キャンペーン
### アオバ工業の設備資金案件
### 窓口待ち時間改善
### NISAセミナー
### 本部報告
### ATMポスター

## 6. 未決事項・確認が必要な点
| 項目 | 不明／未決の内容 | 確認先（明示されている場合のみ） | 根拠時刻 |
|---|---|---|---|

## 7. 議事録作成上の注意
- 音声が不明瞭なため未確認の箇所
- 表示名を参加者名へ変換した箇所
- 相対日付のまま記載した箇所
```

## 5. アクション項目の書き方

- 担当者・内容・期限を分離する。期限がなければ「未設定」と明記。
- 状態は「決定」「対応予定」「未割当」「要確認」などを使い分ける。
- 同一タスクを発言回数の分だけ重複計上しない。
- タスクの根拠時刻は、担当者・期限が読み取れる関連発言の時間帯を記載する。
- 読み手がZoom文字起こしへ戻って検証できるよう、`00:03:31–00:04:22` のようなタイムスタンプを付ける。

## 6. 品質チェックリスト

- [ ] Zoom表示名と実際の会議参加者を照合したか
- [ ] 会議日が不明なままなのに具体日付を作っていないか
- [ ] 決定・指示・検討・未決定の区別をしたか
- [ ] アオバ工業の融資金額を捏造していないか
- [ ] NISAセミナーの日程・予約確定を捏造していないか
- [ ] ATMポスターの担当者を勝手に割り当てていないか
- [ ] 待ち時間改善の具体策を実施決定と誤認していないか
- [ ] 本部報告用数値の収集期限を推測で決めていないか
- [ ] 不明瞭・重複した音声認識の影響を確認したか
- [ ] 重要な決定とタスクに根拠時刻を付けたか
- [ ] 業務メモ③の前回議事録と今回の新規決定を区別したか
- [ ] 業務メモ①限定の情報を今回の発言と誤認していないか
- [ ] 指示語の補完根拠が業務メモ①にある場合、それを示したか

## 7. AIに与える実行指示の例

「添付のZoom文字起こしを議事録にしてください。業務メモ①（背景情報）・業務メモ②（議事録フォーマット・作成ルール）・業務メモ③（前回議事録）を参照し、指定の見出し構成で作成してください。確認できない内容は推測せず、『未決定』『要確認』『未設定』を使って区別してください。各決定・アクションに根拠となる発言時刻を記載してください。」
